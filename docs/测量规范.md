# 测量规范：口径、工具、样本量、判定

**适用版本**：v0.25.1 起 ｜ **为什么有这一页**：这个项目三次把「量纲/口径」搞错（naive CI、8 万局当独立样本、A/B 用单臂 SE），而口径以前只散落在消息和脚本注释里，换个人接手就断。**任何「A 比 B 强/弱」的结论，先按本页选口径，再报数。**
标记沿用交接口径：**【实测】** 有脚本有样本；**【估算】** 有依据的推断；**【未验证】** 只有代码或注释。每个数字后面都给了复现方式。

## 1. 三类测量，三张表，不许混用

| # | 用途 | 数据形态 | 标准误 | 80% 功效能测到 |
| --- | --- | --- | ---: | ---: |
| ① | **发布主指标**：挑战 vs 专家（一次运行内换座位） | 每 seed 两局，按 seed 配对 | **17.80**（15,200 局） | **+50** |
| ② | **改动 A/B**：基线与变体各跑一批**同一段 seed** | 两个配置逐 seed 相减 | **2.3 ~ 7.0**（15,200 局，随改动类型） | **+6.4 ~ +19.6** |
| ③ | **HLB**：挑战 vs 专家打同一脚本化 bot | 逐手相减（两档同一副牌） | **35.2**（每 bot 1,800 手） | 正向 **+99** / 判负 ≤ **−69** |

同一个「15,200 局」在①②下分辨率差 **3.6 倍**。用①的样本量去验②的门槛是浪费，用②的灵敏度估①是自欺。
②的范围不是含糊其辞：**求解器类**（开关影响整条决策链）实测 `sdDiff=6.11`→SE **7.0**；**旋钮类**（只动一个参数）实测 `sdDiff=1.76`→SE **2.3**。每次 A/B 必须报 `sdDiffBB` 再反推，见 §5。
**唯一写法**：15,200 局 = **7,600 seed** = 8 片 × 950（15,100 除不尽 8，已废弃）。

## 2. 配对标准误

每 seed 打两局（换座位、同一副牌），两局净胜相关，不能当独立样本。设每局净胜 sd = σ、同 seed 相关系数 = ρ、seed 数 = H：

```
SE(BB/100) = 100 · σ · √(1+ρ) / √(2H)
```
- ρ=0 → `σ/√(2H)`（乐观）；ρ=1 → `σ/√H`（换座位白打）

| 配置 | H / 局数 | σ(BB/局) | ρ | 旧口径 CI | **正确 CI** |
| --- | --- | ---: | ---: | --- | --- |
| 挑战 vs 专家 | 40,000 / 80,000 | 18.41 | **0.4212** | [−6.5, +19] | **[−8.9, +21.5]** |
| 专家 vs 专家（同代码自对打） | 1,500 / 3,000 | 16.40 | **1.0000** | [−103.6, 13.7] | **[−128, 38.1]** |

**ρ 恰为 1 的情形**：两边同档时，座位互换后是同一局棋的镜像，`net(seat0) === net(seat1)` 逐位相同 → **有效样本只有 H，旧 CI 窄 √2 ≈ 41%**。
复现：`npx tsx scripts/h2h-combine.ts tmp/ctl-ee-*.jsonl`（看 `corrSameSeed`）。
实现上不用单独估 ρ：**把每 seed 两局取平均当一个观测，对 H 个观测求标准误**，两个极端自动落在正确位置。

| 脚本 | 读这个 | 不要读 |

| `h2h-combine.ts` | **`pairedBySeed.ci95`** + `corrSameSeed` | 顶层 `ci95`（旧） |

| `h2h-diff.ts` | `delta.ci95` | — |
| `hlb-compare.ts` | `verdict` | — |

同一批数据、同一个点估计 +18.1，**两套口径给出相反结论**。

## 4. 工具与命令

| 脚本 | 职责 |
| --- | --- |
| `h2h-shard.ts` | 分片跑：`HAND_START`/`HANDS` 按 **seed 序号**切片；`HANDS` 是 seed 数，局数 = 2×`HANDS` |
| `h2h-combine.ts` | 合并 JSONL；缺片/重复 → exit 1 并列出缺的手号 |
| `h2h-diff.ts` | **同 seed 两批的逐 seed 配对差分**（`基线... -- 变体...`） |
| `hlb-bots.ts` / `hlb-compare.ts` | 6 个确定性 bot（session 口径）／挑战 vs 专家打同一 bot 的逐手差分，输出 `verdict: REGRESSION/OK` |

```bash
# ① 主指标：8 片 × 950 seed（约 20 分钟）
for i in 0 1 2 3 4 5 6 7; do NEW_CHALLENGE=1 OLD=0 HAND_START=$((i*950)) HANDS=950 \
  OUT=tmp/main-$i.jsonl npx tsx scripts/h2h-shard.ts > tmp/main-$i.log 2>&1 & done; wait
npx tsx scripts/h2h-combine.ts tmp/main-*.jsonl          # 读 pairedBySeed.ci95
# ② 改动 A/B
npx tsx scripts/h2h-diff.ts tmp/base-*.jsonl -- tmp/var-*.jsonl   # 读 delta.ci95 / delta.sdDiffBB
# ③ HLB（每 bot 1,800 手 × 两档）
BOT=three-bet-caller CHALLENGE=1 HANDS=1800 OUT=tmp/hlb-1.jsonl npx tsx scripts/hlb-bots.ts
BOT=three-bet-caller CHALLENGE=0 HANDS=1800 OUT=tmp/hlb-0.jsonl npx tsx scripts/hlb-bots.ts
npx tsx scripts/hlb-compare.ts tmp/hlb-1.jsonl tmp/hlb-0.jsonl   # 读 verdict
```
**`h2h-diff.ts` 自校验**：两批 `(hand,newSeat)` 集合必须完全一致且内部无重复，否则 exit 1；自比自必须 `Δ=0 / CI=[0,0]`（已验）。漏写 `--` 也会 exit 1（故意不猜）。
**吞吐【实测】**：8 进程 **12.5 局/秒**（4 进程 11.7，4→8 只涨 7%，**不要开 16 片**）。15,200 局 ≈ 20 分钟，80,000 局 ≈ 107 分钟。
**长跑必须分块**：本环境后台任务约 **18 分钟收 SIGTERM**（实测两次被砍）。单块 **≤8 分钟**（4~6 片 × 475~760 seed），续跑用「算缺口 + 补片」，并靠 `h2h-combine` / `h2h-diff` 的自校验兜底（缺片/重复会 exit 1，不许手工合并绕过）。

## 5. 功效换算表（80% 功效 = θ/SE ≥ 2.80）

| θ | 单臂 @15,200 局（SE 17.8） | 单臂 @29,000 局（SE 12.9） | A/B-求解器 @15,200（SE 7.0） | A/B-旋钮 @15,200（SE 2.3） |
| ---: | ---: | ---: | ---: | ---: |
| +10 | 8% | 12% | 30% | **99%** |
| +15 | 13% | 21% | 57% | 100% |
| +50 | **80%** | 97% | 100% | 100% |

读法：**主指标问 +50 用 15,200 局**；**A/B-求解器**问 +15 只有 57% 功效（要 80% 得 19,600 局），**A/B-旋钮**问 +10 已经 99%。单臂系数 `SE=2195/√局数`（σ=18.41、ρ=0.4212）；A/B 系数按类型：求解器类 `SE=611/√seed`（sdDiff 6.11）、旋钮类 `SE=200/√seed`（1.76）。
**⚠️ 旧的 4.3 是 60 seed 的试点值，已被实测取代**（求解器 A/B 15,200 seed 得 6.11；原型 A/B 得 1.76）。**每次 A/B 都要看 `delta.sdDiffBB` 再反推样本量**，不许套本表——同一个 15,200 局，SE 可以是 2.3 也可以是 7.0。
**另一类问题：结构 vs 比例**（`_diag-*` 的引擎命中率、各街决策占比）。**60 手只够看结构**（哪个引擎命中过、有没有走到求解器），**不够看比例**：单格 95% CI 起手就 ±10pp 左右，且同一手内多次决策相关、有效样本比「决策数」更小。**比例类结论要 ≥500 手并标【估算】**；60 手给出的百分比只能当线索。分母固定时还要注意**跳档**（如 41 次只能按 2.44pp 跳：26/41=63.4%、27/41=65.9%；本项目 P1-3b 的降级目标最终定为 **≥60% = 25/41**，余量只有 1 个决策）。

## 6. 判定规则

1. 点估计变差且 CI 不重叠 → **不许合并**（修或明确回滚）；CI 重叠 → 写「在噪声内」，不许写「提升」。
2. **< 7,400 局的结果只能写「方向性观察，未达显著」**（= 单臂 +50 的 CI 下界>0 门槛）。
3. **联合门槛禁止合并**：`点估计 ≥ T` **且** `CI 下界 > 0`，当 1.96×SE < T 时前半句蕴含后半句，联合通过率 = P(点估计 ≥ T)。主指标必须**分两行**报：I-G1 显著（下界>0）、I-G2 幅度（点估计 ≥ +50，不要求同时显著；**2026-11-10 起降级为报告项**，见第 8 条）。
4. **关闭线用 CI 上界**：Δ 门槛的「关闭」判据是 `CI 上界 < T`（而不是点估计为负），否则会把噪声判成退化。
5. 每次跑批记 `corrSameSeed`：**从 0.42 掉到 <0.25 说明配对失效**（两边行为差异过大），此时配对 CI 会退化成单臂口径，要回查测试台。
6. **单臂数字跨 seed 段不可直接比**：同配置换一段 seed，点估计能漂 6 个点（实测 0..15199 的 **+12.1** vs 全量 80,000 局的 **+6.3**，单臂 SE≈17.8，两者都在噪声内）。两个单臂数字来自不同 seed 段时，必须标「**未配对，不可比**」；要比就用 `h2h-diff` 配对。
7. **先验作用面，再验效应量**（变更由主理人依实测发起）：任何新层/新开关，跑判定批次之前先用同 seed 两批逐手比对 `net`，**有差异的局数占比 > 0 才算生效**；占比 = 0 时 Δ 只能落在 0 附近，那批机时全是浪费。实例见 §8 第 5 条。
8. **绝对水平不可验收**（变更由主理人依实测发起，2026-11-10）：单臂每手 sd 实测 **18.34 BB**（会话模式测量台，4 组 × 1,000 手），按 80% 功效反推：

   | 想检出的真实差异 | 需要手数/臂 |
   | ---: | ---: |
   | ±50 BB/100 | 5.2 千 |
   | ±30 BB/100 | 1.43 万 |
   | ±20 BB/100 | 3.23 万 |
   | ±10 BB/100 | 12.9 万 |
   | +20 BB/100（80% 功效） | **13 万** |

   口径：前四行 = **单臂 95% CI 半宽**等于该值（1.96σ）；最后一行 = **两臂对比、80% 功效**（未配对，含 √2 与 2.8σ，故是 3.23 万的 4 倍）。两种口径不可互换。

   本项目单次跑批受 18 分钟限制、最多约 1,000 手（§4），**±20 BB/100 及以下的量级在这个测量能力下不可判定**。故：任何「领先 X BB/100」的表述**必须同时给出样本量与 95% CI**；**样本 < 1 万手时禁止使用「显著领先」「吊打」「更强」这类措辞**，只能写「方向性观察，未达显著」。实例（同一份代码 4 组各 1,000 手：−52.3 / −72.1 / −58.1 / −72.0，去重合并 n=2,000 → **−63.6 [−144.0, +16.7]**）说明「跑一批就有结论」是错觉——区间宽度 161 个点。

9. **测量期间代码冻结**（变更由主理人依实测发起，2026-11-10）：跑批开始到结束，任何人不得修改 `src/`、`scripts/`，也不得切分支 / 改训练产物。本项目已两次因此产生不可信数据（一次翻前层、一次蓝图重训期间）。需要改代码就**先中止跑批并作废已跑的片**——`h2h-combine` 只能校验缺片与重复，**校验不出「中途换了代码」**。跑批前后各记一次 `git rev-parse HEAD` 与 `git status --porcelain` 的空输出，写进结果备注。

10. **样本独立性检查**（变更由主理人依实测发起，2026-11-10）：合并多组跑批前，必须确认 **seed 不重复**（并按 seed 段核对「这段是不是被别的改动用过」，见 §7 台账）。实例：`session-h2h.ts` 的 seed 曾**不含 `ARCH`**，导致 `assign` 与 `fixed` 两臂是**同一副牌重跑**，合并时被当成 2 倍独立样本、**CI 虚缩 √2**；去掉重复后 n=2,000 而非 4,000。判定方法：合并前先比对两批的 `(hand, newSeat)` 集合与 seed 列表，重叠即 exit，不许手工平均。

## 7. 选择偏差：多臂选优必须换 seed 确认

4 臂取最大，赢家虚高 ≈ **E[max of 4] ≈ 1.03σ**（A/B-求解器 σ≈7.0 → 约 **+7 BB/100**，正好吃掉一半的 +15 门槛）。**规则**：选臂 `HAND_START=0..7599`、确认 `7600..15199`（不重叠，各 7,600 seed），确认批次仍为正才采纳；成本多 20 分钟。

### 留出集管理规则（变更由主理人依实测发起，2026-11-09）

**留出集用一次就消耗掉。** 每次判读必须记录「这段 seed 被哪个改动用过」，并写进本节台账。新改动一律取最后一段之后的新区间。

理由：重复使用同一段会让「确认」退化成「再测一遍」，选择偏差无法消除——**用过的留出集比没有留出集更危险，因为它看起来是干净的**。

**留出段台账**（新判读前必须先在此登记；已登记的段不得再用于新改动的判读）：

| seed 段 | 用途 | 消耗者 |
| --- | --- | --- |
| `0..7599` | 选臂（多臂取优） | P1-4 closeness 四臂选臂；翻牌层选臂集 |
| `7600..15199` | 历史确认段——**仅用于与翻牌层/转牌层对账，不得用于新改动的判读** | 翻牌层确认（+6.8）、转牌层确认（+6.0） |
| `15200..22799` | **当前可用留出段** | 已分配给 PRD P0-7 翻前层（7,600 seed / 15,200 局） |
| `22800` 起 | 未分配 | — |

**通用教训**（`交接说明书` §1.4.2）：任何「A 比 B 差」先问三件事——**同 seed 吗？同参数吗？测量工具的前提假设有没有被破坏？**

| 5 | **先测效应、后查作用面**（变更由主理人依实测发起）：新层/新开关在目标决策路径上到底会不会触发，从没确认就直接跑 15,200 局 | **「作用面」先于「效应量」**：任何新层/新开关，测效应之前必须先确认它在目标决策路径上真的会触发。确认方法：同 seed 跑两批，逐手比对 `net`，**有差异的局数占比 > 0 才算生效**；占比为 0 就是死代码，此时任何 Δ 测的都是噪声 | 河牌延伸实测 **Δ=−0.1**，事后查明河牌只有「面对下注」才由单街求解器接管，其余路径没有作用面——先测效应再查作用面，白花 20 分钟机时 |

## 10. 维护约定

- 改 `h2h-shard` / `h2h-combine` 的对局循环或统计公式后，**必须重跑等价性**：`HANDS=250` 直跑 vs `HAND_START=0 HANDS=250` 分片，要求 `shard.ci95 == head2head.ci95Naive` 且 `combine.pairedBySeed.ci95 == head2head.ci95`（2026-11-08 三方对账通过）；改 HLB bot 逻辑后跑确定性自检（`hlb-bots.ts` 头注释），两次 JSONL 逐位相同，并重跑 §5 的 sdDiff 更新 §1、§9。
- 数字对不上时，**先怀疑测量台，再怀疑 AI**。
